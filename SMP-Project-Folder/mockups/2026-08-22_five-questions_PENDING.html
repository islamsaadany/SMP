Question 2 · Navigation

Sixteen destinations behind one gear

“let's think of some sort of grouping for the settup tabs. and an easier view for it. maybe a collapsable rail on the left for easier navigation think with me.”

Thinking with you, in three steps

First: the menu is doing two unrelated jobs. Six of its entries are things you do during a cycle — open it, chase it, import a plan, mark focus measures. Ten are things you set once and revisit rarely. They sit in one alphabet-free list because they arrived one at a time, not because they belong together. Splitting them is free and it halves the problem before any design happens.

Second: a rail is not a new component. The platform already has one — it is what a unit's pillars sit in, `.rail` inside `.split`, 236px beside the pane. Using it for Setup means Setup starts looking like the rest of the product rather than like a settings screen bolted on. That argues strongly for the rail over, say, a row of tabs, which would be a new thing to design and would run out of room at ten.

Third: what the groups actually are. Not by which table they edit — by the question you came to answer. That gives four groups of two to four, and every page lands in exactly one:

Who

Who exists, and what may they touch?

  • People
  • Roles & access

What we run

What are the things being planned?

  • Business units
  • Companies
  • Supporting functions
  • Capabilities

How it's measured

What do the numbers mean?

  • Figure sets
  • Scoring bands
  • Labels

How it looks

What does it wear?

  • Branding

The one I'd push back on: collapsing to an icon strip. Ten setup pages need ten icons, and “Labels” versus “Scoring bands” versus “Figure sets” have no icons anybody guesses right. A collapse that hides the only thing that identified the page is a control you have to learn. If the rail must collapse — and there is a real reason, the access matrix wants 940px — I'd collapse it entirely, to a 46px strip with one “open” handle, and let the group letters be the only marks. Shown as Option B so you can see it lose.

Question 3 · Fill a figure set

One searchable table, every unit in it

“make the tables searchable not categorized by direction like this… the 1st column become a numbering column… we can have the table for all units as a default so we have the unit as a column that can be filtered by… accordingly the units names at the top are not usable… so the table is pushed up and accordingly we have a sticky header.”

Agreed, and the reason is that the two jobs want opposite shapes. Grouping by pillar is right when you are reading one unit's plan in plan order. Filling a set is the other job entirely — you are hunting for the eleven revenue lines in a hundred and sixteen figures, and pillar order actively hides them from each other. A flat searchable table puts every “revenue” in the group on one screen.

Seven columns, and each earns its place. # numbers what is currently shown, so “11 of 116” is countable. Unit is a column you filter, not ten buttons you press — every unit is in by default, which is the whole point of a set that crosses them. In is how key objectives join the same table: a pillar code, or the words Key objective. Measure and Target are separate columns so search hits the measure name and never the number — typing revenue cannot match 4B EGP. Status is the tick, or another set's name with a request beside it. The header is sticky and the unit buttons are gone, so the table starts 120px higher.

Question 4 · People

Still too tall, and the reset was hiding in plain sight

“the people table is still large with no need, remove view as from this table and still I can't find the reset passwords actions in this page.”

The reset action is there — I signed into a live instance to be sure. The Password column renders, and the button says Reset. The reason you cannot find it is that it is a bare text link at 12px in the sixth of seven columns, with no border and no fill: it reads as part of the sentence rather than as a thing you press. It is a findability bug, not a missing feature. Below: an obvious button, View as removed, and the last of the height taken out.

What I need from you

  1. Pillar title — A, B or C? I'd take B. Say if you want theme and owner kept, in which case it is C.
  2. Setup rail — is the grouping right? Four groups, named by the question you came to answer. Say if a page is in the wrong one, or if you want the collapse built at all. And confirm the split: does Manage stay a menu while Setup becomes a page with this rail?
  3. The fill table — anything missing from the seven columns? In particular: should Compile be there (I left it out — it is the plan's business, not the filler's), and should the search also match the unit name, or is the Unit filter enough?
  4. People — anything else on the row? Contact is the one column I would question next; it is empty for almost everybody.
