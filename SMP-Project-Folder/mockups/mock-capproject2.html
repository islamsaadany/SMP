Two milestones finish after this project's end date of 30 Apr 2026. Saved exactly as entered — the platform does not refuse a date. The project has run past its timeline and one of two things is true, so it asks rather than deciding:
Why a deliverable is not a milestone. A milestone answers when — it carries a finish date and is either reached or not. A deliverable answers whether — it is a thing that now exists, and it can be half-built. Oracle form development is a date; the Oracle-based interest utilisation form is a thing. If a row cannot be given a finish date it is not a milestone; if nobody receives it, it is not a deliverable.

The owner's note on this cycle

This number can fall, and it is not a defect. Before Q2 the Oracle project read 88% on its deliverables alone, both outcomes still unmeasurable. Q2 brought 20 hours against a target of 40 and performance dropped to 69%. It moves again at Q4. Because a drop will be reported as a bug the first time it happens, the page has to keep saying which outcomes have been read and which are still waiting — which is what the dimmed not asked row does, the same way a tactic outside its quarters is dimmed today.
