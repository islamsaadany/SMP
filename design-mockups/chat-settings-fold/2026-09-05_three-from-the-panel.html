The wiring is already right, and that is a measurement rather than a reassurance. The server reads that box's value at the two places that decide when a collection email goes out, so typing 25 genuinely moves the email to twenty-five minutes. Nothing is hard-coded, and nothing needs building for that half.

What is wrong is only the words: the row reads [10] 10 minutes, saying the number the box is already showing. It becomes [10] minutes — visible in every picture below.

One thing it does not change The sentence on the ⓘ hover still reads “anything left unanswered for 10 minutes…”, with the number. A label beside a box and a sentence explaining a rule are two different jobs, and only the label is repeating itself.

Three — the Setup page hands over its whole screen

the whole settings page look like that when squeezed can we fix this?Islam

It is a regression, and it came from another session rather than from this work. §267.2 moved the shared .split layout from stacking at 820px to stacking at 1200px — a deliberate, argued decision for a unit’s pillar rail. Setup’s page wears that same .split, and the change was not scoped away from it, so Setup began stacking at 1200 too — while its own narrow treatment still starts at 900. Between those two numbers the rail is a full-width, window-tall scrolling column and the page you actually opened is pushed below the fold.

This project has recorded that exact trap once already, in §158: “.pane INCLUDES SETUP — so scope any pane rule with :not(.setuppane) or it reaches the register.” Same fault, different class name.
