The strip on one deck

A master flow labels the strip by subject — MB, RS, FIN — so you can see where you are and jump. One unit's deck still draws one blank dot per slide: 28 of them for Mobile, which you can count and cannot read. Three ways to give it the same strip. Press the pills — they move the slide.

Deck: Strip:

A · sections

One pill per part of the deck, in words: Cover · Foundation · SWOT · Pillars · Performance. Five pills for a 28-slide deck.

The cost, measured: the four pillars are one pill, so there is no way to jump to MB03 — the jump a review actually makes. And a function that plans in projects has no dividers at all, so Marketing's whole strip is two pills: COVER · END.

B · sections + codes

The same, with each pillar getting its own code — the letters already printed on every one of its slides, and exactly what the master flow does with a subject's code.

The cost: ten pills instead of five. Measured on Mobile they are 573px and sit on one row at every width from 1920 down to 1024; Merchandising is seven, Marketing four.

C · grouped dots

Keep one dot per slide and group them, with a hairline between sections and the section you are in drawn brighter.

The cost: it is still 28 dots and still says nothing — you can see that a section changed, not which one you are going to. And it does not fit: 998px of dots on Mobile, wrapping to a second row at every width measured, 1920 included.

This is a drawing, not the product. The slides, their headings and their order are read out of the real decks — Mobile is 28 slides, Merchandising 16, Marketing 15. Nothing here changes what a deck holds: the sections are ones the deck already declares (its blue dividers, each pillar's title page, each capability's cover), which is the same list the picture placer has used since it was built. A capability has no code, so B falls back to two letters, exactly as a subject with no prefix does in the flow.
