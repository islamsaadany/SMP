Four fixes: the welcome screen, the dates, and the type column

Every picture below is the shipped platform driven in a browser with the proposed change injected into the live page — not a drawing made from the stylesheet.

Nothing here is built yet
01

Viewing as, on the welcome screen

The welcome screen covers the window, so the Viewing as control in the bar underneath cannot be reached while it is up. Switching person redraws the welcome screen for them, so you see what they are greeted with. Only a Super user session gets it — the same answer the bar already asks, never a second rule.

B is my recommendation. The chips already say who you are and where your roles are held; the control sits with them and changes exactly that. In A it floats above the greeting on the page’s own ground, reading as furniture that belongs to no part of the screen.

What it costs B adds about 30px to the hero. The role line the bar normally prints after the control is dropped here, and only here — the chips directly above already say every role and where it is held, so it would say it twice.

02

Sign out, sign in — and no welcome screen

Nothing to draw: this one is behaviour. The screen remembers “seen” for the browser session, and signing out only reloads the page in the same tab — so the memory survives and you are not greeted again. A session that simply expired behaves the same way.

Now
Sign out, sign back in — no welcome screen until you quit the browser.
After
Signing in clears the memory, so every sign-in greets you.
Unchanged
A plain refresh still does not greet you again. That was the point of it.

What it costs Nothing on any screen. One line at the door, where the session actually begins.

03

A project’s Start and End — picked, as Jul 26

Start and End get the same month picker your milestone due dates already use: click a month, step the year, Clear to empty it. Nothing is typed, so nothing can be mistyped.

This is not only a look. On your own tenant that End date reads 30/4/2026, and the platform cannot read it at all — so the warning that says “N milestones finish after this project ends” can never appear on that project. 1/1/2026 reads as January only by luck: slashes are read month-first, so 3/4/2026 would read as March, not April. Jan 26 reads one way everywhere.

What it costs — three things, all real Dates already written are not touched. A project still showing 30/4/2026 keeps showing it until somebody opens the pen and picks — the platform will not guess whether that means April or something else. A quarter can no longer be set as a Start or End, the same trade you accepted for milestone due dates. And the overrun warning has to be repaired in the same change: it reads dates with the browser’s own reader, which turns Jul 26 into 26 July 2001 — left alone, this change would wake a dead warning as a wrong one that fires on every milestone.

04

Deliverable and Outcome as plain text

One place builds that box and all three project pages use it, so this is one change everywhere — Plan, Performance and Reporting.

What it costs Nothing moves. The column keeps its width so the two words still line up under one another and no other column shifts — and the rows come in 17px shorter across the six, because the chip’s padding was setting the row height. Say the word if you would rather the column shrink to the words instead.
