Fill the gaps

A third level of Strategy access between View and Edit: the custodian or the BU owner writes only where the plan says Missing. A fill stays theirs to correct until the Strategy Office confirms it; performance is computed only over confirmed numbers; reporting and drafts flow freely, but Submit waits.

ARoles & access — the Strategy cell gains a middle state

Same cell, three toggles instead of two. The new mark is a pen over a dashed line — writing into the blank. Lit, it wears amber: the same colour every pending value wears, so the grant and its consequence read as one family. Nothing changes for any tenant until the SMO lights it.

The pen opens only the blanks. Everything already written stays as text — no field, no ×, no “+ Add”, no drag handles. A red dashed box is a gap to fill; an amber box is their own fill, still correctable because the office hasn’t confirmed it yet.

EReporting — drafts flow, Submit waits

The refusal sits where the confirmation would be, names the rows, and says whose move it is — the unit has nothing of its own to fix here, so the words must send them to the right person, not back to their fields.

2 targets are awaiting Strategy Office confirmation (MB-KM2, MB-KM5). Reporting and drafts are unaffected — submitting opens when the office confirms.

A pending owner or date never blocks Submit — only the fields a score reads: target, direction, compile rule. The same line the dash draws, so the product gives one answer, not two.

Not in this mode, by decision: adding or removing rows, renaming anything, reordering (its own grant, unchanged), and touching any confirmed value. On the plan deck, a pending value prints as the value with a light “(pending)” — answered, not settled — never as Missing.

Settled in this thread — what this mockup draws

  • Third state on the Strategy cell: View / Fill gaps / Edit; nothing changes until the SMO lights it; a role only ever fills a unit or function it holds.
  • A gap is a place holding nothing — the same list the deck already marks Missing; one definition shared by screen, server and deck.
  • No rows added or removed in fill mode.
  • Filled → pending → confirmed: a fill stays editable to fill-grant holders until the office confirms; confirming removes the mark; a confirmed value is the office’s alone.
  • Reporting is never held up; performance is computed only over confirmed targets, with the dash saying why.
  • Submit is refused while a score-bearing field is pending; Save draft always works.
  • Server-authoritative throughout: the screen offers, the authoriser decides — fill, amend-while-pending, and confirm are three server rules.
