What this decides, and what it does not

  • Office only, by rule. The page reads every person's changes, so it is gated like the Platform Inbox — the office's, never a matrix cell. A unit head gets the one line on their own page and the door to their own unit's rows only.
  • Restore is an ordinary save. It writes the old value back through the same door every change goes through, so it is authorised, merged and logged — and a restore can itself be restored. It is never a database rollback.
  • Some rows have no Restore. Submitting a report is reopened from the Reporting tab, where it always was; a row added or removed is put back from the plan archive. The button is greyed with the reason on hover rather than missing.
  • Nothing new is written. The log has been written on production since §42; this page only reads it. The one server addition is a filtered read of the log (person, place, kind, day) so the page never loads the whole history.
  • What it cannot recover. Work that never reached the server — a refused stale tab, a lost connection before the save landed — leaves no row. The banners are what stands in front of that.
