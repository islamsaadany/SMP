Build the plan, in the row’s own menu

First entry, above the rule with the other authoring acts — Clear progress and Clear plan are below it because they take something away. The same entry goes on Setup › Functions.

What it changes about the builder Nothing, except how it is reached. The chip map, the titled forms and the band that follows you are untouched. What goes is the chooser dialog — “Whose plan is this?” — because this table is the picker, and creating a subject is already this page’s Add button (which, measured, already opens the builder’s own new-unit form).

The chooser also carried a real decision: building over a standing plan archives it. That question moves into the menu’s own confirm panel — the shape this table already uses, shot here unedited from Clear progress:

Cost: the entry is on every row, so on a subject that already has a plan it always asks. That is the safer way round — the alternative is an entry that appears only on empty subjects, which is a door you cannot go looking for.

The cycle, on Download

  • This cycleThe live figures, complete. The plans as they stand.
  • A closed oneIts figures come from the archive taken when it closed — and that archive is already named after the cycle.
  • Every fileNames its cycle on the Read me sheet and in its filename, so a file on somebody’s disk answers the question without the platform.

The one gap, stated rather than discovered. A plan archive records the subject and the date it was archived, never the cycle. So Plans from a closed cycle can be answered from today onward — I would stamp the running cycle onto new archives, which migrates nothing — and the archives already stored can only show their date.

The Upload half — which of these did you mean?

You chose pick any cycle, closed ones included. Two very different things sit behind that, and they differ by weeks of work, so I would rather ask than guess a third time.

A — a cycle that is closed but not succeeded

The cycle is closed, no new one has opened, and its figures are still live. Uploading reopens it and applies the file.

Small. Reopen already exists on Setup › Reporting cycle (§273.2) — the upload would use it rather than invent anything.

B — correcting a cycle that has passed

A new cycle has opened since, so that cycle’s figures are in an archive. Uploading edits the archive.

Its own feature, not this page. The score HISTORY recorded at close would no longer match its own figures unless recomputed, and the authoriser has no case today for editing an archive — so it needs a rule, a change record, and a decision about the score.

Say A and I build the whole page now. Say B and I build the page with A’s behaviour and put B on the backlog as its own change. Nothing in src/ has been touched.
