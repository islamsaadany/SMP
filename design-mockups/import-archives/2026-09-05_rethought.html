Files in, files out

You did not like any of the three, and you were right to say so: all three tidied the page that is there. This one changes what the page is. It also takes Build a plan off it, as you asked — with one thing you have to decide, because that band is the only door into the guided builder.

Why those three were wrong

They all kept the shape and straightened it. The shape is the fault: the page is a tutorial — 1, 2, 3 — for something nobody does in one sitting. You take a file, it goes away for a week, somebody sends it back. Numbering those as consecutive steps makes the whole page furniture for anyone who has done it once, and it forces the same question to be answered twice: which kind of file? on the way out, and again on the way back.

Straightening a row cannot fix that. So this pass throws the steps away.

“Build a plan” leaves — and it is the only door

You are right that the plan can already be authored where it lives: the pen and the + Add a row buttons on a subject’s own Foundation, SWOT and Plan pages write it directly. But the amber band does something narrower, and it is the only thing that does it.

Measured data-buildplan appears exactly once in the whole product — that band — and openBuilderChooser() has no other caller. Remove it and the guided builder (spec 020: the chooser, the chip map, the titled forms, the band that follows you) becomes unreachable code.

Which is §61’s trap, and §24 says unreachable code does not get left lying about. So the band comes off this page either way, and where the builder goes is your call:

Give it a door where it is needed

On a subject’s own empty Plan page — where somebody actually is when they have nothing planned yet, rather than on a page about files.

Delete it

The pen already authors, and the chooser’s extra step — or create one — is what Setup › Business units and Setup › Functions already do. Deleting a shipped feature is yours to say, not mine.

The file already says what it is

This is what lets the page lose its worst control. The Plan | Progress switch governs both halves of the page, and on the way back it asks a question the file has already answered.

Measured Every workbook the platform writes carries a Read me sheet whose first cell reads Plan workbook or Progress workbook, and whose second names the subject. A progress workbook also carries an ID column on every sheet; a plan workbook cannot, because §22 says a plan arrives with no codes and the platform mints them. Two independent ways to tell them apart, both written by our own builder.

So on the way out you press the row for the file you want, and on the way back the platform reads the file and says what it found. The switch is deleted, both directions — not restyled.

The page

Two things, named in the order they happen to a file. Nothing else on the page.

  • OutFour rows, one shape: what it is, who it is for, one button. Export everything is a row, not a special case — which is what it should be, because it is another file you can take. The next one added is another row.
  • InOne control. No kind, no subject — the file carries both.
  • GoneThe step numbers, the mode switch, the two bare CSV links (now a quiet also as CSV on the row it belongs to), the raw Choose File, the amber band, and the heading that repeated the tab.
  • UnchangedThe review table, the checks, the refusals, Apply and Discard, the archives tab, §22’s contract, and every rule on the server. This is the page around them.
  • New wordsThe bar names the file — Progress workbook · Mobile — which is the one thing the old page never said, and the place a file that cannot be read should have been saying so all along.

What it costs. The upload has to identify the file, which is new behaviour rather than new layout — a workbook somebody rebuilt by hand with no Read me falls back to the ID test, and a file that answers neither is refused by name. And a .csv is unambiguously progress, since a plan cannot arrive as one.

  2. The builder — a door on an empty plan page, or delete it.
  3. The page’s name. It is called Import & archives and it is about to export. Files & archives is my suggestion; the rail key does not move, so nothing anybody has saved is affected.
