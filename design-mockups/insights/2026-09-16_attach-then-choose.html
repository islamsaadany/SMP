Attach, then choose the exit

Today a report must be saved before a file can be attached. This draws the flow Islam described instead: fill it in, attach the file, see it confirmed — and then choose between keeping it as a draft and publishing it. Nothing about the security rule moves: the store path is still built on the server from the report's own id. What changes is that creating the row stops being something you press and becomes something that happens.

The record

What this decides, and what it costs

Settled

Attaching a file is the ordinary act. Saving a draft and publishing are the two ways of finishing, and neither stands in front of the file.

Changes

A report starts existing when you attach, not when you press save. That is what lets the strip honestly say the file is up.

Still required

A title — because a draft with none is a row nobody can pick out of a list. Empty when you attach, it says so and puts the cursor there. One field, not a press.

Unmoved

The store path is still built on the server from the report's own id. No browser ever names it. Every piece is still authorised on its own.

Removed

The switched-off file button, the “Save it first” line, and with them the small keyboard problem that button had.

Noticed, not folded in

A held Publish is drawn exactly like a live one — the console styles no held state. The refusal works; it is only invisible until you hover. Its own small round, on your word.

Cost

Attach and walk away and a draft is left behind. It is visible, it is deletable, and nothing is lost — which is the whole of why a warning here states a fact rather than raising an alarm.
