Being offline lasts as long as it lasts

So it has to be closeable

A dialog that cannot be dismissed means nobody can touch the platform until the connection comes back — a tunnel, a lift, a hotel wifi. The work is safe on screen and typing more of it is safe too, so locking the page would cost real work to say something the page has already said.

Keep working and the × both close it. What they must not do is leave the screen silent, because the work still is not stored.

What is left after it is closed. The small card from the last round, in the one bottom corner the Strategy Office bubble does not occupy. It stays until the work is saved, and it goes by itself when the save lands.

The one real cost of the centre

The platform has exactly one dialog, and it may be in use

Every dialog in the product opens in the same element — opening one overwrites whatever was in it. So if a save fails while somebody is halfway through the person dialog or the merge wizard, an offline message using that element would destroy the dialog they were working in.

The fix is not complicated and it is not free: this message gets an overlay of its own that stacks above, and closing it must put the page back the way it found it rather than releasing a page another dialog is still holding.

The other two ways a save fails

A save fails three ways and only one of them is being offline. A person meets one at a time and has to tell them apart, so all three wear the same dialog.

Online, and no answer. The browser’s “Failed to fetch” goes to the console, where the one person who can act on it looks.

The server answered with an error. The number stays deliberately — it is what sends somebody to the right place.

What stays a banner

A refusal is a different message: the server has decided this person may not make one of these changes, and it names the rows and offers two ways out.

This one is not moved. Its list grows with the number of rows, and both buttons have to be read before either is pressed. Say if you want it centred too and it is drawn again.

How it behaves

  • It opens the moment a save fails, wherever you are in the platform.
  • Once, not every five seconds. The platform retries constantly while it is offline; the dialog is raised for the episode, not for each attempt, or closing it would achieve nothing.
  • It closes itself when the save lands — and so does the corner card. Coming back online clears everything within about five seconds, with nothing to press.
  • Escape closes it, like every other dialog in the platform.
  • Never on a projector. Presentation mode drops it, the way it already drops the chat bubble.
  • The work is genuinely waiting, not lost. Measured, not assumed: the retry runs for as long as the tab stays open. Closing the tab while offline still loses it, which is why the dialog says not to reload.
  • The chat corner is left alone. It has the same blind spot in its own message. You named the save error, so it is flagged here rather than widened quietly.
