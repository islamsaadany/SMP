What you see today

A strip across the top, in the browser’s words

The exact banner you photographed, reproduced at a 1000 px window.

  • It is a strip at the top of the page — far from where you were typing, and it pushes the page down as it arrives.
  • It does not say the one thing you need. You are offline, and the sentence talks about the server — which sends you to look at something that is working perfectly.
  • “Failed to fetch” is the browser talking. It is not a status number anybody can act on, and it names nothing.
  • The advice is backwards while you are offline. It tells you to reload, and reloading is exactly what would throw the work away.
  • The two sentences run into each other. …(Failed to fetch).Your change… — no space, on every failure the platform has ever reported, not only this one.
Proposed

The same card the chat corner is made of

The platform already floats one card over the page — the Strategy Office corner. This is that box: the same white, the same hairline, the same corner radius and shadow. The only thing added is a red edge, which is how the platform marks what kind of message something is without turning the whole card into an alarm.

Shown at its real size — 360 px wide, which is the chat panel’s width. Three lines, and the heading answers the question before you read any of them.

The other two ways a save fails

A save fails three ways and only one of them is being offline. A person meets one at a time and has to tell them apart, so all three wear the same card.

Online, and no answer. The browser’s “Failed to fetch” goes to the console, where the one person who can act on it looks.

The server answered with an error. The number stays deliberately — it is what sends somebody to the right place.

What stays a banner

A refusal is a different message: the server has decided this person may not make one of these changes, and it names the rows and offers two ways out.

This one is not moved. It carries a list that grows with the number of rows and two controls that have to be read before either is pressed — a 360 px card in the corner is the wrong shape for it, and a decision you must take should not sit where a passing notice sits. Say if you want it moved too and it is drawn again.

How it behaves

  • It appears when a save fails, and stays while the work is unsaved. It does not stack: one card, rewritten.
  • It goes by itself. The platform retries every five seconds while the tab is open, and a save that lands takes the card away — so coming back online clears it within about five seconds. Nothing to press.
  • No close button, recommended. The card is the only thing saying the work is not stored; a × would let it be dismissed while that is still true. Say if you want one — the alternative is that closing it shrinks it to a small marker rather than removing it.
  • Never on a projector. Presentation mode drops it, the way it already drops the chat bubble.
  • The work is genuinely waiting, not lost. Measured, not assumed: the retry runs for as long as the tab stays open. Closing the tab while offline still loses it, which is why the card says not to reload.
  • The chat corner is left alone. It has the same blind spot in its own message. You named the save error, so it is flagged here rather than widened quietly.
