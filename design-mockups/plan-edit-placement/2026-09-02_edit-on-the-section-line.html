The plan’s Edit button, on the Foundation · SWOT · Plan line

What is there today, measured; what the measuring found that the ask did not mention; and three placements drawn into the real platform so one can be picked.

01

The short answer

Yes — and half of it is already there. When the plan is open for editing, that line already carries the way out. It says Done filling, it is drawn as plain uppercase words rather than a button, and nothing on that line offers the way in. So this is less a move than a correction plus one addition.

On the second question: within a business unit and a supporting function, the edit pen is only on the Strategy tab. Performance and Reporting carry none. Two edit surfaces sit outside it — the group’s own Foundation and Temple — and neither has a section line to move onto, so both stay exactly as they are.

03

Three things the measuring found

None of these was in the ask; all three are answered by the same move.

The line already holds the way out, wearing the wrong word and no dress

With the plan open, the section line renders Done filling at x 1341 — class editbtn fdone, data-page="plan". Two faults. The word is wrong: the office is editing, not filling. And it is undressed — computed background: rgba(0,0,0,0), border: 0px, ink #414A58, which is an unselected tab — because .tabs button (0,1,1) outranks .editbtn (0,1,0). §145.14 gave the chips and the red button a second selector for exactly this reason; this one control was missed.

For the office, the red button on that line already opens the pen’s mode

Fill in what is empty calls enterFillMode(), which sets EDIT_PAGE[page] = true — the same switch the pen throws. For anybody with a fill grant it means something narrower; for the office it is the pen under another name, and then walks to the first blank. Two controls, one state — §94.15’s argument.

Foundation and SWOT cannot be edited from a tablet without guessing

Both pens are visibility:hidden until their card is hovered. On a 1024×1366 touch viewport they measured hidden until the card itself was tapped — so the first tap does nothing you can see, and nothing says where to tap. §70 fixed this for the plan pane in August (“on a touch screen there is no hover at all… which is where a plan gets corrected”) and left the cards behind. Moving the control onto the line closes it for both, without touching the hover rule.

05

Three placements

Each drawn by moving the platform’s own control in the live page — both sides are this same build, so nothing here is a picture of a different product.

B  —  a worded control at the end of the line, and the red button steps aside for the office

Recommended

The count and the red chips stay where they are and go on saying what the plan owes. What leaves, for the office only, is the red button — because for them it opens the very mode Edit opens. Anybody with a fill grant sees the line exactly as they see it now.

A  —  the same, with the red button kept beside it

Works, but says one thing twice

Identical to B except that the office keeps both doors into the same mode. Honest about what each does, and one more control on a line whose job is to say where you are.

C  —  move the pen glyph itself, unchanged

Rejected — and the picture is the argument

The pen is a 28px hollow circle built for the corner of a card, where the card frames it. In a wide tab row there is nothing to frame it, and it all but disappears — look at the far right below. It would also leave the two states saying nothing: a glyph cannot read Done editing, which is the half of the ask about saving.

06

How far it goes — and this is the one thing I need decided

You asked about the plan. The line is shared with Foundation and SWOT.

If only the Plan moves, the control’s home still changes as you switch section — on the line for Plan, in a card corner for the other two — which is a smaller version of the thing being fixed. If all of them move, the slot means one thing everywhere: this section’s pen. It also closes the tablet problem in §03.

A supporting function’s two sections — Overview and Plan (or Projects) — take the same slot, which also puts its worded Edit and a unit’s in one place for the first time.

07

It holds at a narrow window

Free space on the line after the tabs: 1248px at 1500, 848 at 1100, 748 at 1000, 648 at 900, 568 at 820, 508 at 760.

08

What it costs

  • The pen leaves the pillar band and the project band. On a function with two projects that removes a second control that was doing the same job — a gain — but it does mean the control is no longer beside the thing it edits.
  • The gold Done editing is one more filled control on a page that already has the Reporting tab in orange. It is only drawn while the mode is open, so the two are rarely lit at once, but it is spending from the accent budget (§41).
  • The group’s Foundation and Temple are untouched, so the platform will have two homes for an edit control until those pages are looked at separately. Worth naming rather than discovering later.
09

What I need from you

  1. B, or A?

    B drops the red button for the office because it opens the same mode. A keeps both.

  2. The plan only, or the whole Strategy tab?

    The whole tab is my recommendation — one slot, one meaning, and it makes Foundation and SWOT editable from a tablet.

  3. The two words: Edit and Done editing?

    Done filling is what the line says today for the office, and it is wrong. If you would rather it read Save, say so — but nothing else in the platform calls it that, because the platform saves as you type.
