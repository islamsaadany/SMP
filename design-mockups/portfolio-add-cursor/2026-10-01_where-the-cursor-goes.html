Where the cursor goes after you name something

Drawn out of the running platform — every box, colour and spacing below is the product's own, lifted from the served page. Only the focus ring and the text caret are drawn by hand, because a still picture cannot hold them. Nothing here is built.

What happens today, measured in a browser and read back out of the database. You name WP one and press Enter. The platform puts you back in the box you were typing in — which is the one that makes work packages. Type Interviews next and you get 1.2 Interviews, a second work package beside the first, instead of 1.1.1 Interviews underneath it. The tree, the numbering and the saving are all correct; only the cursor is in the wrong box.

Option C — recommended
Follow in only where there is nothing to guess

A work package holds one kind of thing — activities — so after naming one the cursor goes into it. A phase can hold either a work package or an activity, so after naming a phase the cursor stays where it is, because the platform cannot know which you meant. At the moment you reported, C and B draw the same picture; they differ one step earlier.

Recommendation
Option C, and take A's wording with it

C is the only one that is right about both the thing you reported and naming a run of phases, and the line it draws is one the platform already has: a work package can hold one kind of thing, so there is nothing to guess; a phase can hold either, so it stays put rather than guessing. Its one cost — naming two work packages back to back — is the least common of the three, and A's wording makes it visible rather than silent. A on its own changes no behaviour, so it would leave your sequence exactly as it is today.
