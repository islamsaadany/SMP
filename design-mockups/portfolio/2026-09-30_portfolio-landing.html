What is owed next

What this screen is

  • It does two jobs. You pick a project, and you see what is owed across all of them. Nothing else is on it.
  • The across-projects reading has nowhere else to go, which is why it is here. Every other tab in Portfolio is about one project by construction, so what does this client owe next could only ever be answered on this page.
  • Somebody sent a link to one project lands in that project, not here. And a client with one project lands in it too, because a list of one is a door behind a door.
  • Every figure is derived from the plans themselves. The Culture row reads 59% because that is what its own phases average to — the same number its Analytics tab reads, off the same rows. A stored per-project percentage is the fault this module spends its spec warning about, and the reference product has two such columns that nothing ever writes.

Who sees which projects, and why that is not a new setting

  • A seat on the client reaches every project; everybody else reaches the projects that name them. That was decided when the module was, and the switch above is here to show it rather than to be built. Rania holds a seat and is named on projects, which is the normal case rather than an edge.
  • Omar sees two of the five and is told nothing about the other three — not a greyed row, not a count. A row he cannot open would only tell him something exists.
  • He sees each project's own state, not only his part of it. A Contributor reads the whole plan of a project that names them, so the Culture row says the same thing to both people. What is his — the box with his name on it, late — is Progress's, and is deliberately not repeated here.
  • Add a project is drawn for a seat and absent for him. Not disabled: a control that refuses is still a control somebody has to ask about.

The row, and the one state that is easy to draw wrong

  • Sales Capability Build has no plan at all, and that is on purpose. It is what every project looks like on its first day, and a row reading 0% over 0 of 0 activities reads as a broken row rather than a new project. It says Not planned and gives no figure, because there is nothing to give.
  • The window is the plan's, never the charter's. What was agreed and what is happening are two facts, and the charter is where the agreed dates live — putting them on this row as well would be two drawings of one thing, which is the fault above. So an unplanned project shows no window either.
  • Behind and awaiting sign-off are separate marks because they need separate people. Late work needs whoever is doing it; work waiting to be accepted needs the Lead. A single needs attention mark would send both to the same place.
  • What is owed next is a rule, not a number of rows: anything overdue anywhere, plus each project's next commitment. So it grows exactly as the list above it does rather than by a cut-off somebody has to defend later.
  • Something both late and finished says it is waiting, not that it is late. The blueprint draft was due in February and the work is done — it is sitting with a Lead. A red 18 days over would send somebody chasing the person who has already finished, so the badge names what is actually in the way and the date beside it stays red. Both facts are on the row; only one of them is the job.
  • Every commitment says how far away it is, and the colour is the only judgement. The first drawing said To come past a threshold — a word doing the colour's job and telling nobody how long they had. How much warning something deserves is the one number on this page somebody chose rather than derived: fourteen days, and it is the same fourteen the Analytics tab uses — because the landing first wrote thirty, and two numbers for one idea is the fault above wearing a tidier coat.

Three things to settle

  • The order. Sorted by name, with the marks doing the work — which reads properly at five projects and probably not at twenty, where whatever needs attention should come first. The alternative is worst-first, and the cost of it is that the list reorders itself as the work moves, so you cannot learn where a project sits.
  • Where a finished project goes. Procurement is done and is still in the list with a Done word on it. It could drop to the bottom, or leave the list for an archive — which is a decision about whether a closed engagement is still part of the portfolio, and not one to take in passing.
  • Whether the strip should count what is yours. It counts the client's work today. For Omar it could instead say what has his name on it — but that is Progress's own question one level down, and answering it twice is how two screens come to disagree.
