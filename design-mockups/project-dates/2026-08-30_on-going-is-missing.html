A date the platform cannot read

You asked that a project marked On‑going reads as missing, and that filling it opens the date panel. The filling half already works — I drove it: On-going is counted as a gap today (FIN01 shows 1), and the fill control is the month‑and‑year panel. What is missing is on the page.

The red word is what the eye catches, and it is the word the count uses — so the bar and the page agree at last. The value is still on the screen, which is the rule this has to keep: somebody is being asked to correct On‑going, and hiding it would leave them correcting something they cannot see. Cost: the row is a few characters longer.

The value keeps its place and the tag says what is wrong with it. Cost, and it is the reason I do not recommend it: red type on a value means this figure is off track everywhere else in the platform. Using it for this is not a date gives one colour two jobs on the same screen.

Filling it — unchanged, and already built

End Missing

Pressing it opens the month‑and‑year panel, which opens on the cycle's year with nothing chosen — because On‑going names no month, and guessing one would be the platform inventing a date. This is what the product does today; nothing here changes it.

My recommendation: A. It makes the page say the word the count is already using, keeps the value visible for whoever has to correct it, and does not borrow the off‑track red for a second meaning.

And one thing that is not on this page: a plan uploaded from Excel still takes On-going into a project's Start or End without a word — a milestone's due date is checked and refused, and these two are not. I would fix that in the same change.
