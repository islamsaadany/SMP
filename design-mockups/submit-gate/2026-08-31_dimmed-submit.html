Design review · 31 August 2026

Submitting an incomplete report

Submit stays dimmed until every figure is entered and the plan has nothing missing. Screenshots are the real platform with the proposed bar injected.

“We need to remove the ability of people to submit a report that is not complete … the submit to SMO should be dimmed with a hover noting that he can’t submit until full reporting of all numbers … and of course they shouldn’t be able to submit if they still have something missing in the plan itself.”

The bar today

Now Submit is always live. It refuses on press, in a pop-up box, after you have already tried.

Proposed

New Not ready — quiet outline. Same size and position, so nothing moves when it becomes live.

Save draft keeps its full colour: parking the report is still the thing you can always do.

New The reason, on hover. Opens downward so it never covers the navigation.

It opens on hover and on keyboard focus, so the reason is reachable without a mouse. Only the lines that apply are listed.

New Nothing outstanding — unchanged. The solid orange returns, exactly as it is today.

What blocks a submission

ReasonNew?Who can clear it
Figures not entered — a row asked this cycle with no number YesWhoever reports
Items missing in the plan — no owner, no quarters, no target YesThe office, or a filler where the grant allows
Said In progress and never said how far—Whoever reports
A figure at risk with no note—Whoever reports
A filled value awaiting the office’s confirmation—The office

The last three already blocked a submission. What changes is the first two, and that all five are now said before the press rather than after it.

This is what caught Consumer Finance

Nine CF tactics have no quarters ticked at all. The platform reads that as “not happening this cycle”, so it never asked for them — the report read 3 of 3 and was submitted as complete.

  • Measured: strip the quarters from a tactic and its unit’s report drops from 41 rows to 40. The row simply disappears.
  • A tactic with no quarters is already counted as a plan gap, so the new second rule blocks that submission.
  • Once the office ticks the quarters, the tactic becomes due and CF can report it — fixed through the plan, not through a special case.
One thing this does not do Until somebody sets those quarters, CF still has no box to type in. Blocking the submission stops the false “complete”; it does not by itself give them the rows back.

Costs, before you agree

Reports already submitted will re-open as incomplete CF currently shows Submitted. With the new rules its report is 3 of 12 with a plan gap, so if it is reopened it cannot be submitted again until the quarters are set. That is the point of the change, but it will look like something broke.
A gap only the office can fix blocks the unit A unit head can be stopped by something they have no control to change. The hover says which, so it is a message rather than a dead end — but they will have to ask the office.
The server still accepts an incomplete submission This is a screen rule. Anyone driving the API directly could still submit. No worse than today — the existing three rules are screen-only too — but worth knowing now that submission is meant to be gated.
