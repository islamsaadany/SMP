Design review · for sign-off

A tactic is judged by what it produced

Every tactic gets a description, an outcome, and the outcome gets the same three things a key measure has — a direction, a target with its unit, and a compile rule. The tactic is then scored on that number instead of on somebody’s estimate of how done it is.

Reported today An estimate Every tactic is asked “% delivered”. Nobody can check it, and two people would give two answers for the same work.
Reported after this A fact 62 against a target of 90. The same shape a key measure has, so the score is arithmetic rather than judgement.
The size of the fill 0 of 83 Tactics carrying an outcome today, across ten units and the pillars function. Every one becomes a missing item to be filled.

There is no such thing as a tactic with no outcome

An earlier draft treated some outcomes as un-measurable — Raya & I2 unified customer base, one Raya dashboard. That was wrong. Those are outcomes, they are simply not written as numbers yet, and they can be: one unified customer base is a target of 1 #, reached or not. So a tactic without an outcome is not a category — it is a gap, counted and filled like any other.

The bridge, and where it ends. Nothing in the product can write an outcome today, so on the day this ships every plan owes 83 of them. A tactic that still has none keeps being asked “how far have you got”, so no reporting round stops mid-flight — and that question disappears from each tactic the moment its outcome is written. It is a way across, not a second way of scoring.

One honest cost

Nine columns overrun by 77px at a 1000px window; from 1100 up it is clear. The cheapest thing to drop is Collabs., which is a plan fact already on the Plan table. I have not removed it — say the word.

One change underneath, and it is not cosmetic

A pillar’s execution today averages the raw reported number, which works only because every tactic reports a 0–100 “% done”. Once an outcome can be 3 stores or 1.6 B EGP, averaging the raw numbers would put 3 alongside 62 and the pillar’s figure would be meaningless.

So execution averages each tactic’s score instead of its actual — the same change we made to the measures a fortnight ago, and the same arithmetic. No unit’s number moves until outcomes and targets are entered, because a tactic still on “% delivered” scores exactly what it scored before.

What building this involves

  • Description and outcome need no migration — both are stored on every tactic today. The outcome’s direction, target and compile rule ride in the same place a milestone’s collaborators do, so they need none either.
  • The workbook gains three columns on the Tactics sheet — outcome direction, target and compile. Without them, downloading and re-uploading a plan would wipe every target you had set.
  • A pen that can write them. Neither description nor outcome has an editor anywhere in the product today, so the plan can hold them and nobody can put them there.
  • The outcome joins the missing count, the fill flow and Next gap — and the server has to accept a fill of it, or the screen would offer a box the save refuses.
  • Submit gets stricter as plans fill. A tactic with an outcome and no figure is a row still owed, exactly like a measure — so a unit cannot submit past one.
  • All ten units and the pillars function, from one table builder. The review deck would carry the outcome on the tactic slide in the same pass.
