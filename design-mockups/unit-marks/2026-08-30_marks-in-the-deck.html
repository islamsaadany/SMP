Why they were not showing, and what was done

Nothing was broken and nothing was deleted. I drove every step of it rather than reading the code:

What was missing is the other half: the seed only ever runs once, on a completely empty database. A tenant created before the marks shipped never received them, and nothing had ever filled them in since. The code was right the whole time and the data never arrived — which is exactly why it reads as “they disappeared”.

Migration 032 fills a unit’s mark only where there is none. Proved on a real Postgres against a tenant built to predate the marks: all ten filled, byte-identical to the shipped artwork, a mark somebody had already set left untouched, and running it twice changes nothing.

The one cost, stated Setup › Business units has a Remove button. A unit whose mark was deliberately taken away would have it put back — once. The migration runs a single time per database, so removing it again sticks.
